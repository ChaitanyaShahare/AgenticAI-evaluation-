# Configuration reference

Every configuration file is strict: an unknown key stops the run with the file, the key path and what to fix. Models
are in `evalkit/config/loader.py`; a new key is added there and on this page.

| File | Section |
|---|---|
| `configs/eval.yaml` | [eval.yaml](#configsevalyaml) |
| `projects/<name>/project.yaml` | [project.yaml](#projectsnameprojectyaml) |
| `projects/<name>/agents.yaml` | [agents.yaml](#agentsyaml) |
| `projects/<name>/tools/specs/*.json` | [Tool specs](#tool-specs) |
| `projects/<name>/policies/*.yaml` | [Policy files](#policy-files), [pii_masking.yaml](#pii_maskingyaml) |
| `configs/pii_recognizers.yaml` | [pii_recognizers.yaml](#configspii_recognizersyaml) |
| `configs/gates.yaml` | [gates.yaml](#configsgatesyaml) |
| `configs/judges.yaml` | [judges.yaml](#configsjudgesyaml) |
| case YAML, reference trajectories | [Case files](#case-files), [Reference trajectories](#reference-trajectories) |
| `.env` | [Environment variables](#environment-variables) |

**Human-owned files.** Policy files (`projects/<name>/policies/*.yaml`), `configs/gates.yaml` thresholds and S1
expectations are written by a person (the QE Lead) and never generated by an AI assistant: if the system and its oracle
come from the same assistant, their errors correlate and tests pass for the wrong reason. While such a file is blank
(comments only), the checks that need it are reported as `skip` with the reason, and the gate verdict is `NO_GATES` —
nothing passes on missing evidence.

| File | Owner | Read by |
|---|---|---|
| `projects/<name>/agents.yaml` | engineer (describes the system) | slicer, AG-4, BF-4, BF-5 |
| `projects/<name>/policies/<rules>.yaml` | **QE Lead** | policy engine (TR-3, TR-4, BF-2, TU-7, AG-5, decision rules …) |
| `projects/<name>/policies/pii_masking.yaml` | **QE Lead** | BF-1 |
| `configs/pii_recognizers.yaml` | engineer (detection only) | BF-1 |
| `configs/gates.yaml` | **QE Lead**, approved by the release approver | `evalkit gate`, `evalkit grade` |

## agents.yaml

```yaml
version: 1
agents:
  <agent name>:                  # the name the system uses in its run events
    role: orchestrator | specialist
    description: text
    slice: <state key>           # the only state key this agent writes (SLICE-1); specialists only
    contract: module.path:Model  # Pydantic model its output must validate against (AG-4)
    output: agent_result | decision   # orchestrator: decision
    prompt: path/to/prompt.md    # relative to the project folder; BF-4 checks replies never repeat it
protected_attributes: [gender, religion, region]   # BF-5: no scorer may receive these
scorer_tools: [compute_score]                       # BF-5: tools that compute a score or decision
pair_patterns:                   # optional; catalogue patterns read by the group checks
  injection: ["Adversarial / injection"]            # BF-3: compared with the clean twin
  fairness: ["Fairness pair"]                       # BF-5: compared with the pair partner
```

Allow-lists are not configured here: each tool spec names its owner in `x-agent`, and any call by another agent is a
TU-7 S1 failure.

## Policy files

```yaml
policy_id: <id>
version: v1
owner: <name of the person who wrote and reviewed the rules>
source: <where the rules come from — catalogue sheet, regulation clause>
validated: false          # true only after SME sign-off; until then S1 results are reported as unvalidated
rules:
  - id: <rule ID as in the catalogue>
    kind: required | precedence | forbidden | implies | allow_list | approval_token | slice_isolation | limit
    description: <the rule in words; shown when it fails>
    metric: <metric ID>   # optional; default per kind (below)
    severity: S1          # S1 (default) | S2 | S3
    agent: <agent name>   # optional; attributes the check to one agent (AG-5 guardrails)
    # … kind-specific keys
```

### Rule kinds

| Kind | Default metric | Keys | Fails when |
|---|---|---|---|
| `required` | TR-3 | `requires: [call …]`, optional `before: call`, optional `when` | a required call did not happen before the `before` call (or anywhere in the run, without `before`) |
| `precedence` | TR-4 | same as `required` | same check, read as an ordering rule |
| `forbidden` | BF-2 | `call`, optional `when` | the call happens while `when` holds (evaluated on the steps before the call) |
| `implies` | TR-3 | optional `when`, `expect` | `when` holds (or is absent) and `expect` does not |
| `allow_list` | TU-7 | — | a tool is called by an agent other than its spec's `x-agent` |
| `approval_token` | TU-7 | `call`, `arg` | the token argument was not issued by an approval step before the call, or appears in customer text |
| `slice_isolation` | TR-3 | — | an agent's output keeps keys outside its contract, or a stray slice went unreported |
| `limit` | TU-5 | `max_attempts`, `max_delegations`, `max_steps` | attempts per identical call, delegations per agent or Supervisor steps exceed the bound |

A *call* is a tool name, or `{tool, args: {path, <match>}, result: {path, <match>}, ok: true}` to narrow it
(`ok: true`: the call succeeded). Shared conditions go under `definitions:` and are reused with YAML anchors
(`e2e: &e2e …` then `when: *e2e`).
A specialist replaced by an L2 stub, or given as canned state (L1 Supervisor cases), counts as having made its own
calls for `required` / `precedence`.
A rule whose condition never held is reported as `skip` ("not triggered"), so coverage shows which rules a run exercised.

### Conditions (`when`, `expect`)

One key per mapping; `all: [...]`, `any: [...]` and `not: {...}` combine them.

| Condition | Holds when |
|---|---|
| `called: tool` or `called: [tools]` | any of the tools was called |
| `succeeded: tool` | a call returned a usable answer |
| `failed: tool` | the tool was called and never succeeded |
| `fault: tool` | a fault was injected on the tool |
| `result: {tool, path, <match>, every?}` | a call's result matches (`every: true`: all calls match; true when not called) |
| `args: {tool, path, <match>, every?}` | a call's arguments match |
| `output: {agent, path, <match>}` | the agent's latest output matches |
| `end_state: {path, <match>}` | the system-of-record state after the run matches |
| `reply: {<match>, scope: any \| final}` | a customer reply matches |
| `user: {<match>}` | a customer turn matches |
| `guard: <rule>` | the system's own guard with that rule fired |
| `approval: APPROVE \| DENY \| NO_RESPONSE` | the approval step gave that decision |
| `case: {level \| pattern \| severity \| primary_agent \| case_id: value or [values]}` | the case has those properties |
| `inputs: {path, <match>}` | what the run was given matches (e.g. `form.customer_type`) |
| `equal: [ref, ref]` | two values are the same; a ref is `{output: {agent, path}}`, `{result: {tool, path}}` / `{args: …}` (last call), `{end_state: {path}}` or `{inputs: {path}}` |

Matchers: `equals`, `not_equals`, `in`, `not_in`, `gt`, `gte`, `lt`, `lte`, `contains`, `matches` (regular expression,
case-insensitive), `exists: true|false`, `nonempty: true|false`. With no matcher the path must have a value.
Paths are dotted (`hits.0.score`); `*` expands a list (`candidates.*.score`).

### Example (a toy lending policy — not the KYC rules)

```yaml
policy_id: toy_lending
version: v1
owner: A. Reviewer
rules:
  - id: L1
    kind: required
    description: credit check before any disbursement
    before: disburse_loan
    requires: [credit_check, {tool: verify_income, result: {path: status, equals: VERIFIED}}]
  - id: L2
    kind: forbidden
    description: never disburse after a fraud flag
    call: disburse_loan
    when: {output: {agent: fraud, path: flagged, equals: true}}
  - id: L3
    kind: implies
    metric: BF-4
    severity: S2
    description: say it is an AI when asked
    when: {user: {matches: 'are you (a )?(human|bot)'}}
    expect: {reply: {matches: '\bAI\b'}}
```

### Catalogue rule kinds → engine kinds

The catalogue's *Rules & Decisions* sheet is the source for the KYC policy file. Its *Kind* column maps as follows:
Required steps → `required` · Precedence → `precedence` · Forbidden → `forbidden` (an allow-list rule → `allow_list`)
· Approval → `approval_token` · Decision → `implies` · Limit → `limit` · Transparency → `implies` with `reply` /
`user` · State isolation → `slice_isolation` · Versioning → `implies` with `result` / `args` and `every: true`
· Masking → `pii_masking.yaml` (below).

## pii_masking.yaml

```yaml
masking:
  policy_id: <id>
  version: v1
  owner: <name>
  validated: false
  rules:
    - id: <rule ID>
      entity: IN_PAN          # an entity of configs/pii_recognizers.yaml
      scopes: [replies, decisions, step_text]
      severity: S1
      description: text
```

Scopes: `replies` (what the customer saw) · `decisions` (Supervisor reasons and messages) · `agent_outputs` (specialist
contracts) · `step_text` (guard and contract notes) · `tool_args` · `tool_results` · `end_state`. A masked value
(`******877U`, `XXXX XXXX 4655`) does not match a recogniser and passes. Evidence in reports is masked to the last 4.

## configs/pii_recognizers.yaml

`recognizers: [{entity, pattern, checksum?, description}]`. `checksum: verhoeff` (Aadhaar) or `luhn` (cards) drops
look-alikes. Recall and precision are measured on `tests/fixtures/pii_labelled.jsonl` (target ≥ 95%).

## configs/gates.yaml

```yaml
version: 1
owner: <name>
approved_by: <release approver>   # null until approved
s1_zero_tolerance: true           # any S1 failure fails the gate
thresholds:
  - metric: TR-1
    scope: suite | agent | pattern   # agent: every agent must meet it; pattern: every pattern must
    patterns: ["Golden path"]        # optional: only cases of these patterns
    stat: pass_rate | mean_score
    min: 0.95
    note: SOP §3.10
report_only: [TR-6, AG-6]         # tracked, never gating
flake_limit: 0.10                 # share of flaky repeated cases that suspends the cycle (SOP §3.5)
judges: {min_kappa: 0.6, min_agreement: 0.85}   # a judge gates only above this, against every tester
weights_e2e: null                 # optional override of the SOP §5.3 composite weights
weights_agent: null
```

Verdicts and exit codes: `PASS` 0 · `FAIL` 1 (an S1 failure or a missed threshold) · `INCOMPLETE` 2 (a threshold
could not be measured) · `SUSPENDED` 2 (too many flaky cases) · `NO_GATES` 2 (gates.yaml blank). SOP §3.10 lists the
starting thresholds; they are calibrated in Week 2 and approved by the release approver.

## Case files

One YAML file per case, `datasets/<pattern folder>/<case_id>.yaml`; the fields mirror the catalogue columns and are
described field by field for testers in `projects/kyc_onboarding/datasets/README.md`. Text columns keep the
catalogue's words; structured fields: `run_sets`, `documents`, `fixtures`, `approver`, `form_updates`, `reference`,
`match_mode` and `expected`. The catalogue's *Lab defect caught* column is never copied (bug-hunt answer key).

## Reference trajectories

`reference_trajectories/RT-xx.json`: `{id, name, tools: [tool names in order], end_state, default_match_mode, used_by,
source, source_text, expansion, reviewed_by}`. `tools` is what TR-2 compares; `source_text` is the catalogue sheet's
wording and `expansion` says how "…" and "×n" were written out. Until `reviewed_by` names a person, TR-2 results say
"not yet reviewed" and lint lists the reference as a note.

## Case fields read by the evaluators

Empty means "not stated" and the check that needs it is skipped.

| Field | Used by |
|---|---|
| `expected.status / risk_tier / risk_score / record / reason_codes` | TR-1, AG-1 (orchestrator) |
| `expected.agent_outputs.<agent>.<path>` | AG-1 (specialists): a value, a matcher (`{contains: X}`) or a list of matchers that must all hold |
| `expected.arguments.<tool>.<arg>` | TU-3, AG-3 — written by the QE Lead from `argument_expectations` |
| `match_mode`, `reference` | TR-2, TR-6, BF-3 |
| `required_tools`, `forbidden_tools` | TU-1, AG-2 |
| `twins` | BF-3, BF-5 |
| `metrics` (from `checks`) | coverage |

## configs/judges.yaml

`version`, `model` (must equal eval.yaml › models.judge), `effort`, `max_tokens`, `rubric_version` (part of the cache
key: change it whenever a rubric or its anchors change), `cache_dir` (relative to the runs folder, so `EVALKIT_RUNS_DIR` moves it too), `metrics: [{id, name, scale_max, description}]`,
`pricing: {input_per_mtok, output_per_mtok, checked_on}` (null until checked against the current price list).
Each metric ID must have a rubric: `TR-8.task`, `TR-8.plan`, `BF-4.explanation` (anchors from SOP §3.9).
Calibration labels are a YAML sheet from `evalkit calibrate --template` (`rater`, `items: [{trace_id, metric, score}]`) or JSONL
rows `{trace_id, metric, rater, score}`; the judge's own scores use rater `judge`, an adjudicated label rater `consensus`.
A judge gates only against the testers' consensus (gates.yaml › judges); until then its checks are S3, report-only.

## configs/eval.yaml › budget (WP8)

`monthly_limit_inr`, `alert_at` (fractions of the monthly limit), `usd_to_inr` (exchange rate), `pricing: {<model>: {input,
output, cache_read, cache_write}}` in USD per million tokens. Null prices make a run's cost "unknown" and switch the
alerts off; nothing is guessed. Every graded run adds a line to `<runs dir>/cost_ledger.jsonl`, from which the
month-to-date spend and the alerts in cost.json are computed.

## configs/eval.yaml

Global run configuration shared by every project. Every value is recorded in the run's `manifest.json` / `RunMeta`;
changing any of them is a full-regression trigger (SOP §3.14).

| Key | Type / allowed | Meaning |
|---|---|---|
| `version` | int | schema version (1) |
| `models.supervisor` / `.specialist` / `.judge` | model ID | model per role; IDs are configuration, never code |
| `effort.supervisor` / `.specialist` / `.judge` | `low` … `max` | `output_config.effort`, pinned per role |
| `max_tokens` | 1024 – 128000 | per model call |
| `refusal_fallback` | bool | must stay `false`: a refusal is recorded and fails closed instead of silently switching models |
| `prompt_caching` | bool | cache the system prompts |
| `max_steps_per_run` | int ≥ 1 | LIMIT-BOUNCE bound on Supervisor steps (TR-5, TR-6) |
| `retry_limit` | int ≥ 0 | LIMIT-RETRY: retries per identical tool call (attempts = retry_limit + 1) |
| `max_bounces_per_specialist` | int ≥ 0 | re-delegations to the same specialist (TR-5) |
| `determinism.as_of` | `YYYY-MM-DD` | the test clock given to every tool |
| `determinism.seed` | int | data generator seed |
| `determinism.lists_version` | text | synthetic sanctions / PEP list version |
| `determinism.risk_policy_version` | text | VER-1: the only source of the risk policy version (`v3`) |
| `trials.S1` / `.S2` / `.S3` | int | k per severity (S1: 3) |
| `run_modes.<smoke\|gate\|full>.select.run_set` | `smoke` / `gate` / `full` | which cases (case field `run_sets`) |
| `run_modes.<mode>.trials` | int or `per_severity` | trials per case in this mode |
| `run_modes.<mode>.judges` | bool | add the advisory judges |
| `run_modes.<mode>.target_minutes` | int, optional | informational |
| `execution.max_workers` | 1 – 32 | parallel trials (lower on HTTP 429) |
| `execution.runs_dir` | path | run output folder, relative to the repository or absolute |
| `budget.*` | see [eval.yaml › budget](#configsevalyaml--budget-wp8) | prices, exchange rate, monthly limit, alerts |

`temperature`, `top_p` and `top_k` are rejected with an explanation: the current Claude API does not accept sampling
parameters; determinism comes from pinned effort, the fixed clock, deterministic mocks and k trials.

## projects/&lt;name&gt;/project.yaml

Paths are relative to the project folder. `module:attribute` references are imported only when a run starts.

| Key | Meaning |
|---|---|
| `project` | project name (= folder name) |
| `data.seed_db` | seed SQLite database copied for every trial |
| `data.generator`, `data.generator_args`, `data.checker` | `evalkit data`: rebuild script, its arguments (`{seed_db}` is substituted), conformance check |
| `adapter` | `module:Class` of the AgentAdapter (KYC: `evalkit.adapters.langgraph_adapter:LangGraphAdapter`) |
| `entrypoint` | `module:function` that builds the system under test |
| `runner` | `module:function` that runs one case × trial and returns the run record (protocol in `evalkit/adapters/base.py`) |
| `case_source` | `module:function` returning the project's `TestCase` list |
| `end_state_query` | SQL run on the trial database after the run; named parameters come from the run record (TR-1) |
| `agents_file` | usually `agents.yaml` |
| `tools_dir` | folder of tool specs |
| `policies` | policy and masking files (human-owned) |
| `gates` | path to gates.yaml |
| `datasets` | catalogue pattern → folder of case YAML files |
| `catalogue` | optional workbook imported by `evalkit cases` |
| `case_import_extras` | optional `module:function` adding setup fields the workbook does not hold |
| `case_lookups.applicant` / `.document` / `.fixture` / `.case_in_seed` | optional SQL used by `evalkit lint-cases` to check IDs exist (`:value` is the ID) |
| `lab_variants` | optional folder of bug-hunt lab variant files read by `evalkit lab` (KYC: `../../training/lab/variants`) |

### Lab variant files

`<lab_variants>/LAB-n.yaml`: `variant` (`LAB-<n>`, = file name), `project`, `switches` (names the project's runner reads
from `EVALKIT_LAB_SWITCHES`), `brief` (what the tester is told; never names the defect). `evalkit lab` sets
`EVALKIT_LAB_SWITCHES` for the length of one run and records the variant in `manifest.json` (`lab_variant`).

## Tool specs

`tools/specs/<tool>.json`, one tool per file (or a file with a `tools: [...]` list, as for the hand-offs):

| Key | Meaning |
|---|---|
| `name`, `description` | as given to the model |
| `x-agent` | the only agent allowed to call it (F4 / TU-7 allow-list) |
| `x-tool-class` | `read`, `interaction`, `write` or `irreversible` (SOP §3.12) |
| `x-fault-modes` | fault types the tool declares (entry criterion, SOP §3.5) |
| `input_schema` | JSON Schema, `additionalProperties: false` (TU-2) |
| `output_schema` | JSON Schema of a successful result |

## Environment variables

Read from the shell or from `.env` (git-ignored) at start-up.

| Variable | Effect |
|---|---|
| `ANTHROPIC_API_KEY` | needed for live runs and judges only; never printed |
| `EVALKIT_RUNS_DIR` | overrides `execution.runs_dir` (keep it outside Dropbox) |
| `EVALKIT_MAX_WORKERS` | overrides `execution.max_workers` |
| `UV_PROJECT_ENVIRONMENT` | where uv keeps the virtual environment (keep it outside Dropbox) |
| `EVALKIT_LAB_SWITCHES` | set only by `evalkit lab`; any other run refuses to start while it is set (never put it in `.env`) |
